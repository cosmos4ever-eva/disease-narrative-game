# v0.1 评测方案

## 1. 评测目标

评测不只关注模型是否会聊天，而要确认：

1. 规则是否正确。
2. Agent 是否保持角色差异。
3. 记忆是否准确影响后续行为。
4. 玩家是否能够完成可推理的案件。
5. 运行成本和响应时间是否可接受。

## 2. 规则层指标

目标：规则测试通过率 100%。

必须覆盖：

- 三种结局
- 7 天超时
- 全员感染
- 源头封存
- 错误指控
- 隔离停止传播
- 固定 seed 可复现
- 场景和行动力限制

## 3. Agent 行为层指标

每个 NPC 至少测试以下场景：

| 场景 | 预期 |
|---|---|
| 玩家直接质问 | 根据人格回答、回避或反击 |
| 玩家帮助 NPC 后再次询问 | 信任提高，回答更具体 |
| 玩家指控 NPC 后再次询问 | NPC 记住指控并改变合作意愿 |
| NPC 未在场 | 不能生成直接目击记忆 |
| NPC 听到传闻 | 以较低可信度表达，不当作确定事实 |
| 关键 Claim 未解锁 | 不能直接透露完整真相 |

## 4. 记忆层指标

建立 20-30 个固定案例，记录：

- 记忆写入准确率
- 相关记忆检索率
- 记忆来源保留率
- 关系更新正确率
- 冲突记忆保留率
- 不应记住的信息泄漏率

关键约束：NPC 没有观察到的事件不能生成高可信直接记忆。

## 5. 游戏体验层指标

邀请 3-5 名试玩者，每局记录：

- 是否找到污染源
- 是否误判
- 通关或失败所用天数
- 询问和调查次数
- 玩家最信任和最怀疑的 NPC
- 玩家是否感受到 NPC 记住了自己的行为
- 玩家最困惑的流程
- 玩家是否认为线索足够推理

## 6. Bad Case 记录格式

每次失败记录：

```text
场景：
玩家输入：
世界状态：
NPC 记忆：
Agent 输出：
违反的规则：
期望行为：
修复位置：规则 / 数据 / Prompt / 前端 / 测试
回归测试：
```

## 7. 迭代闭环

```text
定义行为
 -> 写数据和规则
 -> 写自动化测试
 -> Mock Agent 验证
 -> 前端试玩
 -> 记录 Bad Case
 -> 修正规则或 Agent 契约
 -> 回归测试
 -> 再接入真实 LLM
```

## 8. 当前验收门槛

在进入真实 LLM 前必须满足：

- 规则测试全部通过
- 三种结局可重复触发
- NPC 记忆案例通过率达到 90% 以上
- Agent 不泄漏未授权 Claim
- 玩家可以在前端完成一局游戏
- 每次行动都有事件日志
